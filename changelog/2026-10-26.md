# 2026-10-26

## 修复：`docker compose build dev` 在 `e7913e3` 上失败

上一条重构把 `pyproject.toml` 的 wheel `force-include` 改为 `web/targets/{shared,react,vue}` 三条，但 `deploy/dev.Dockerfile` 只 `COPY pyproject.toml README.md LICENSE` 与 `src`，镜像里没有 `web/targets`。hatchling 即使在**可编辑安装**的元数据阶段也会解析 force-include 路径，于是构建必然失败：

```
FileNotFoundError: Forced include not found: /workspace/web/targets/react
```

该失败与本地改动无关——在干净的 `e7913e3` worktree 上单独 `docker build` 复现同样报错。生产镜像 `deploy/Dockerfile` 一直有 `COPY web/targets ./web/targets`，只有 dev 镜像漏了。

修复：dev 镜像补 `COPY web/targets ./web/targets`。资产只在构建期需要存在；运行时 `./` 挂载覆盖 `/workspace`，仓库自身的 `web/targets` 生效，镜像不额外占用空间。

验证：`docker compose build dev` 成功；`docker compose run --rm dev pytest -q` **296 passed**。

## 清理：删除遗留的 10 个 `.gitkeep`

十个 `.gitkeep` 全部是阶段 0 建目录时的占位，所在目录早已有真实文件被跟踪（`deploy/` 2 个、`src/mocksite/{admin,scenarios,state}` 3/2/5 个、`src/mocksite/site/templates/` 3 个模板、`web/admin/src/{components,features/*}` 1–2 个），占位作用已失效。

影响：`src/mocksite/{admin,scenarios,state}/.gitkeep` 与 `src/mocksite/site/templates/.gitkeep` 会被 hatchling 作为包内文件打进 wheel（上一条记录只注意到 templates 那一个，实测 wheel 内有 4 个 `.gitkeep`），删除后 wheel 只剩 `_static` 16 项 + 3 模板。源码、测试、脚本对 `.gitkeep` 零引用，`git ls-files` 各目录仍有真实文件，目录不会消失。

验证：

- `pytest -q`：296 passed（223 unit + 73 integration，宿主机 conda `webmonitor` 环境）。
- wheel 前后对比（容器内 `hatchling build`）：改前 4 个 `.gitkeep`，改后 0 个；`_static` 16 项与 3 个模板不变。
- 安装改后 wheel 并启动真实 site app：`/health`、`/ssr/product`、`/react/list`、`/vue/list`、`/dynamic/deals`、`/api/data` 均 200，页面只引 `/static/{shared,react,vue}/`，`resolve_asset_dir()` 解析到包内 `_static`。

## 重构：目标页资产按框架归位

`web/targets/` 从 `{assets,vendor}` 两分法改为阶段 0 规划的 `{shared,react,vue}` 三分法：框架无关资产在 `shared/`，每个框架子树自带页面脚本、UMD 运行时与许可证。

### 动机

阶段 0 曾建过 `web/targets/{react,shared,vue}/` 占位目录，阶段 4 实现时改成了 `{assets,vendor}`（页面脚本 vs UMD 库），占位目录在 `bd2e1c1` 中被删除。按框架查找资产（"React 页面在 react 文件夹、Vue 页面在 vue 文件夹"）是原始规划的意图，本次恢复该布局。

### 结构变化

- `web/targets/assets/` 拆分：`list.js`、`deals.js`、`product.js`、`shop.css`、`img/` → **`web/targets/shared/`**；`react-list.js` → **`web/targets/react/`**；`vue-list.js` → **`web/targets/vue/`**。
- `web/targets/vendor/` 拆分：React/react-dom UMD 与许可证 → `web/targets/react/`；Vue UMD 与许可证 → `web/targets/vue/`；`manifest.json` → `web/targets/manifest.json`（清单条目未变，sha512 全部复核通过）。

### 接线变化

- `site/routes.py`：挂载点从 `/static/assets` + `/static/vendor` 改为 **`/static/shared`、`/static/react`、`/static/vue`** 三个；故障中间件豁免前缀（`ASSET_PREFIXES`）与 `resolve_asset_dir` 的探测目录（`shared/` 存在性）同步更新。
- `site/render.py`：`render_list` 向 `list.html` 传 `framework`，vendor 与页面脚本按 `/static/{framework}/…` 引用。
- 模板：`list.html`、`deals.html`、`product.html` 的资产引用改为新前缀；`state/models.py` 与 `render.py` 中的商品图路径改为 `/static/shared/img/…`。
- `pyproject.toml`：`force-include` 从两条改为三条（shared/react/vue → `mocksite/_static/{shared,react,vue}`）。`deploy/Dockerfile` 复制整棵 `web/targets`，无需改动。

### 测试与验证

- 单元/集成测试中所有资产路径更新；`test_every_asset_referenced_by_the_page_is_packaged` 的正则放宽到 `/static/…` 并排除 `/static/product` 页面路由；`test_pyproject_force_includes_every_asset_tree` 改为断言三个子树；manifest 校验按条目的 `package` 名路由到 react/vue 子树。
- `pytest -q`：**296 passed**（223 unit + 73 integration）。
- wheel 实测：构建成功，`_static` 条目 16 个（shared 7 + react 5 + vue 4）+ 3 模板 + 1 gitkeep；安装 wheel 后 `resolve_asset_dir()` 解析到包内 `_static`，三个子树齐全。
- 冒烟（从已安装 wheel 启动真实 app）：React 页只引 `/static/react/`，Vue 页只引 `/static/vue/`，deals/product 页只引 `/static/shared/`，无任何 `/static/assets`/`/static/vendor` 残留；`outage` 下三个资产前缀仍 200、`/static/product` 仍 500。
