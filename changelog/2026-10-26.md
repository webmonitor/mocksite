## 删除：故障注入（500 / 延迟）

早期版本提供 `outage`（业务路由全部 500）与 `slow_site`（延迟 8000ms）两个场景，以及驱动它们的站点中间件、`Faults` 状态段和后台的「故障注入」面板。本轮全部删除。

### 删除理由

采集方如何处理超时、重试与 5xx 是**它自己的契约**，不属于「输入」。把传输故障混进 mocksite 会让两类信号无法区分：页面内容变了，还是网络挂了？验证失败路径应由采集方自带的 fixture 或前置网关完成——`WebMonitor-Agent` 就是这么做的（`tests/fixtures/site.py` 自带可控故障，与 mocksite 无耦合）。

### 删除范围

| 层 | 删除内容 |
|---|---|
| 状态模型 | `Faults`、`FaultKind`、`MAX_DELAY_MS`；`State` 从三键降为 `{revision, business}` |
| PATCH | `MUTABLE_SECTIONS` 从 `("business", "faults")` 降为 `("business",)` |
| 站点监听 | `site/routes.py` 的故障中间件、`ASSET_PREFIXES`、`OUTAGE_STATUS`、`asyncio` 导入 |
| 场景 | `outage`、`slow_site`；`ScenarioGroup` 去掉 `fault`；`PresetScenario.faults` 字段 |
| 后台 API | `/_admin/state` 不再返回 `faults` |
| 后台 SPA | `FaultPanel.tsx` 整个组件、`Faults`/`FaultKind` 类型、四步向导里的「故障注入」区块、概览与恢复步骤里的故障/延迟条目、场景分组的「故障注入」标签 |
| 文档 | README 的故障章节、场景表两行、API 表、阶段表；AGENTS.md 的中间件约定改为「不要加回来」 |

### 兼容性

`PATCH /_admin/state` 收到 `faults` 会返回 **400**（`unknown section`），而不是静默忽略——旧客户端会立刻失败并看到明确原因。有测试锁定这一点：`test_faults_section_is_rejected_as_unknown`、`test_no_fault_injection_remains`、`test_state_rejects_a_faults_section`、`test_state_has_exactly_two_top_level_keys`。

## 重构：演示主题对齐真实高校通知公告系统## 重构：演示主题对齐真实高校通知公告系统

上一版把站点做成「政务收费标准公告」，结构是自拟的。本轮改为对齐真实存在的门户 —— `notice.xidian.edu.cn`、`notice.ysu.edu.cn`、`xxgk.xidian.edu.cn` —— 因为这些才是 WebMonitor 用户实际会盯的页面，它们的 DOM 才是采集器真正要对付的东西。

### 从真实站点抄来的、之前没还原的特征

| 特征 | 出处 | 为什么重要 |
|---|---|---|
| 同一发布时刻渲染成三种形式：`10月20日` / `2026年10月20日` / `2026-10-20 14:32` | YSU 列表项三处 `<span>` | 三处都是「像日期的数字」，误选不会报错；它们都**不是**执行日期 |
| 点击次数由脚本异步填充（`_showDynClicks`） | 西电详情页 | 静态 HTML 里是空的，HTTP 抓取拿到空串 |
| 正文是逐段 `<p>`，非一个文本块 | 西电详情页 | 整页文本比对会被页头页脚干扰，必须定位 `#notice-body` |
| 附件带文件类型与大小 | 两站都有 | `data-kind` 给出机器可读类型 |
| 上一篇/下一篇标题 | 两站都有 | 导航里含**另一条**通知的标题，是标题诱饵 |
| 「共 N 条 1/M」分页 | 西电列表 | 末页判断 |
| 撤回仍可访问（不是 404） | 校园门户惯例 | 采集器必须看到「已撤回」而不是失败 |

### 页面与数据

- 详情页 `/static/notice`、`/ssr/notice`；列表 `/react/list`、`/vue/list`；分页 `/dynamic/archive`。
- `/api/views` 取代 `/api/revisions`：点击次数的 JSON 端点。

### 日期派生

`published_at` 是唯一真源，`render.py:date_parts()` 派生三种渲染，所以三者永不可能互相矛盾：

```
published_at = "2026-10-20 14:32"
  → badge_day  "10月20日"      (#date-badge)
  → full_date  "2026年10月20日" (#published-date-cn)
  → timestamp  "2026-10-20 14:32" (#published-at)
```

前导零在中文日期里被去掉（`1月5日`，不是 `01月05日`），但时间戳保留补零 —— 它是机器可读形式。

## 修复：`docker compose build dev` 在 `e7913e3` 上失败

上一条重构把 `pyproject.toml` 的 wheel `force-include` 改为 `web/targets/{shared,react,vue}` 三条，但 `deploy/dev.Dockerfile` 只 `COPY pyproject.toml README.md LICENSE` 与 `src`，镜像里没有 `web/targets`。hatchling 即使在**可编辑安装**的元数据阶段也会解析 force-include 路径，于是构建必然失败：

```
FileNotFoundError: Forced include not found: /workspace/web/targets/react
```

该失败与本地改动无关——在干净的 `e7913e3` worktree 上单独 `docker build` 复现同样报错。生产镜像 `deploy/Dockerfile` 一直有 `COPY web/targets ./web/targets`，只有 dev 镜像漏了。

修复：dev 镜像补 `COPY web/targets ./web/targets`。资产只在构建期需要存在；运行时 `./` 挂载覆盖 `/workspace`，仓库自身的 `web/targets` 生效，镜像不额外占用空间。

验证：`docker compose build dev` 成功；`docker compose run --rm dev pytest -q` **296 passed**。
