## 已实现：阶段 1 状态内核

- 新增 `src/mocksite/state/models.py`：不可变（`frozen`）状态模型 `State`/`BusinessData`/`Product`/`Item`/`Presentation`/`Faults`，全部 `extra="forbid"`；`revision` 位于 `State` 且只读。价格以 `Decimal` 持有、以十进制字符串出入：仅接受 `<digits>[.<digits>]`（可带前导 `+`），拒绝浮点、指数、负号、非有限值与超过 64 字符的输入，`000128.50` 归一化为 `128.50`。呈现控制使用互斥枚举（`product_price`: `normal|empty|missing|renamed`，`item_price`: `normal|renamed`），避免布尔开关互相冲突。`page_count` 由 `items` 与 `page_size` 派生，不存储。
- 新增 `src/mocksite/state/patch.py`：实现 `PATCH` 语义——对象递归合并、数组整体替换；`null`、任意深度的 `revision`、未知 section/key、类型错误一律拒绝，错误以 `{"loc","msg"}` 列表返回，一次给出全部问题；被拒绝的 patch 不会留下部分更新。
- 新增 `src/mocksite/state/store.py`：`StateStore` 持有一把锁，`_commit_locked` 在同一临界区内完成“递增 revision → 渲染静态页 → 同时替换 state 与 `static_html`”，因此不存在“状态已更新而静态页仍旧”的窗口；渲染抛错时状态与页面都不前进。提供 `patch`、`apply_scenario`、`reset`（均返回前后状态或新状态）、`snapshot()` 原子读取、`register` 场景注册。模块不导入任何 Web 框架。
- 新增 `src/mocksite/scenarios/registry.py`：13 个预设场景（`baseline`、`no_change`、`price_change`、`item_price_change`、`empty_value`、`missing_node`、`structure_break`、`empty_list`、`field_rename`、`duplicate_rows`、`pagination_grow`、`outage`、`slow_site`），每个都从默认数据构造完整目标状态并一次性提交，场景之间不叠加；元数据含 `description`、`affects`、`pages`，供 `GET /_admin/scenarios` 使用。`build_default_store()` 返回已注册全部场景的 store。
- 新增 `src/mocksite/state/__init__.py`、`src/mocksite/scenarios/__init__.py` 导出公共名字；新增单元测试 `tests/unit/test_state_models.py`、`test_state_patch.py`、`test_state_store.py`、`test_scenarios.py`。

## 重构：真实电商详情页 + 向导式管理后台

### 目标

原页面过于精简（商品页 8 个节点、列表 3 行 3 列），无法暴露真实采集中的主要失败模式；原管理后台按「状态总览 / 数据编辑 / 呈现与故障 / 场景 / 目标页面」平铺，暴露 `revision`、`normal|empty|missing|renamed`、`outage` 等内部术语，场景以代码标识符（`item_price_change`）呈现，且改完数据看不到页面实际效果。本轮允许破坏性重构。

### 已实现：商品详情页

- `/static/product` 与 `/ssr/product` 改为真实电商详情页（约 12.5 KB HTML）：工具条、站点导航、面包屑、图库（4 张本地 SVG + 缩略图切换）、标题/品牌/SKU、评分与评价数、价格区、库存、包装与规格变体、数量步进、卖点、描述、规格表、懒加载评价、推荐位、页脚。
- **多重价格节点**：除 `#current-price` 外还有 `#original-price`（划线价）、`.installment-price strong`（分期，约现价 1/4）、`.unit-price strong`（每 100 g，约现价 1/10）、`.msrp-price`（标价段）。误选会取到数值而不是空——这是本次重构的核心测试价值。
- **评价为浏览器端分页**：静态 HTML 只含骨架屏与 `data-state="pending"`；`product.js` 取 `/api/data` 后渲染第一页，才设置 `#reviews[data-ready="true"]` 与 `data-revision`。`/api/reviews?page=N` 同时提供 JSON 分页。
- 状态模型扩展：`Product` 新增 `brand`、`sku`、`rating`、`review_count`、`stock_status`（`in_stock|low_stock|out_of_stock|preorder`）、`stock_count`、`description`、`highlights`、`images`、`variants`、`specs`；新增 `Review` 模型与 `BusinessData.reviews` / `review_page_size`。`Presentation` 新增 `reviews`、`rating`、`gallery` 三个互斥枚举。
- 新增资产 `site/static/assets/{shop.css,product.js,img/*.svg}`，全部本地分发、无 CDN。

### 已实现：场景

场景从 13 个增至 17 个，并为每个场景补充中文 `title`、`outcome`、`selector_impact`、`group`、`compare_with_baseline` 元数据（服务端唯一来源，`GET /_admin/scenarios` 返回）：

- 新增 `rating_missing`（只移除评分数字，星级字符保留——从星级反推会算错）
- 新增 `reviews_empty`（就绪成立但 0 条，与加载失败区分）
- 新增 `reviews_missing`（整块区域不存在，与空列表区分）
- 新增 `gallery_removed`（可选区域缺失，页面其余部分正常）

### 已实现：管理后台

- **向导式四步流程**：① 建立基线 → ② 应用变更 → ③ 核对页面 → ④ 恢复，顶部步骤条显示当前进度与生效场景。
- **内嵌实时预览**：右侧 iframe 常驻显示目标页，任何变更后自动重载。以 1180 px 桌面宽度渲染再缩放适配面板宽度——若按面板宽度渲染，商品页 900 px 断点会把价格区挤到图库下方，恰好看不到要验证的内容。
- **场景卡片**：按「基线 / 价格变化 / 结构变化 / 列表与分页 / 故障注入」分组，每张卡片显示中文标题、采集方会看到什么、哪个选择器失效。
- **字段级变更对比**：应用场景后展示前后状态 diff，而不是只报 revision 跳变。
- **选择器参考按角色分组**：主要目标 / 就绪标记 / 辅助字段 / 诱饵节点，每条带 CSS、XPath、复制按钮与说明。
- 数据编辑改为标签页（商品字段 / 列表行 / 评价），呈现控制改为单选卡片并为每个选项解释采集侧后果。
- 所有错误文案改为可读中文（`ApiError.humanMessage`），不再只显示状态码。

## 范围收敛：移除结构性破坏场景，只保留数据切换

### 需求调整

上一轮为商品页加入了「呈现控制项」（`Presentation`），通过把同一份数据渲染成不同 DOM 形态来模拟结构破坏：节点缺失、节点改 ID、文本为空、单元格 class 改名、图库/评价区整块消失。实际使用后确认这不是本项目要验证的东西——**本项目只验证不同场景下的页面数据切换**，即「数据变了平台是否识别」，而不是「DOM 被改写后提取器如何反应」。提取器的健壮性由使用方自己的测试覆盖。

### 已实现：删除呈现控制层

- `state/models.py`：删除 `Presentation` 模型与 5 个呈现枚举（`ProductPriceRendering`、`ItemPriceRendering`、`ReviewsRendering`、`RatingRendering`、`GalleryRendering`）。`State` 收敛为 `{revision, business, faults}`。
- `state/patch.py`：`MUTABLE_SECTIONS` 从 `("business", "presentation", "faults")` 收敛为 `("business", "faults")`；PATCH 携带 `presentation` 现在返回 400。
- `site/render.py`、`templates/{product,list,deals}.html`：去掉全部 `presentation` 分支，页面骨架无条件渲染。
- `site/static/assets/{list,react-list,vue-list,product}.js`：删除 `itemPrice === 'renamed'` 与 `reviewsRendering === 'empty'` 分支；`td.price` 固定。

### 已实现：场景重排（17 → 14 个，5 个分组）

删除 7 个结构性场景：`empty_value`、`missing_node`、`structure_break`、`rating_missing`、`reviews_missing`、`gallery_removed`、`field_rename`。

新增 4 个数据场景，并把 `reviews_empty` 改为数据语义：

| 场景 | 分组 | 变化 |
|---|---|---|
| `price_increase` | 价格 | 现价 128.50 → 158.00（涨价方向） |
| `stock_out` | 商品内容 | 库存 `in_stock` → `out_of_stock`，数量归零 |
| `rating_change` | 商品内容 | 评分 4.6 → 3.2，评价数 128 → 131 |
| `reviews_grow` | 商品内容 | 评价 5 条 → 7 条，分页 3 页 → 4 页 |
| `reviews_empty` | 商品内容 | 评价清空（原为结构性场景，改为数据语义） |

分组从「基线 / 价格变化 / 结构变化 / 列表与分页 / 故障注入」改为「基线 / 价格变化 / 商品内容 / 列表与分页 / 故障注入」。场景元数据字段 `selector_impact` 改为 `data_impact`。

### 已实现：管理后台

- 删除 `features/scenarios/PresentationPanel.tsx`，新增 `features/scenarios/FaultPanel.tsx`：只保留故障类型（正常 / 500）与延迟（0–30000ms），故障注入功能完整保留。
- `ScenarioPicker` 改为 5 个分组，卡片显示「数据变化」而非「选择器影响」。
- 步骤 ④ 恢复页移除呈现控制项摘要。

## 结构调整：前端资产移回 web/，验收脚本移入 tests/

### 动机

两个长期存在的结构问题：

1. **`web/targets/` 是空壳。** 它是阶段 0 的规划占位（只有三个 `.gitkeep`），零引用；而阶段 4 实现时把 React/Vue 目标页资产放到了 `src/mocksite/site/static/`。结果 `src/`（Python 后端）里混进了前端代码，`web/` 下反而空着，文档还按旧位置描述，三处互相矛盾。
2. **`tests/browser/` 也是空目录**（不在 `testpaths` 里），而真正的浏览器验收脚本在 `scripts/` 下，与运维 CLI `control.py` 混在一起。两个 check 脚本还各自重复实现了 `Results`、绕代理 opener、参数解析、退出码。

### 已实现：前端资产归位

- `src/mocksite/site/static/{assets,vendor}` → **`web/targets/{assets,vendor}`**。`src/` 现在只有 Python：`routes.py`、`render.py`、`pages.py`、`templates/`。
- 新增 `site/routes.py:resolve_asset_dir()`，解析顺序为：`MOCKSITE_TARGET_ASSETS` 显式配置 → wheel 内 `mocksite/_static/` → 仓库 `web/targets`（仅便于可编辑安装）。找不到时抛 `RuntimeError` 并列出搜索过的路径，不再静默返回空目录。
- `pyproject.toml` 用 hatchling `force-include` 把 `web/targets/{assets,vendor}` 复制进 wheel 的 `mocksite/_static/`。wheel 的 `include` 只留模板。
- `deploy/Dockerfile` 在构建阶段 `COPY web/targets`，安装完 wheel 后 `rm -rf /app/src /app/web`——生产镜像运行时**不依赖**仓库里的 `web/`。
- `Settings` 新增可选 `MOCKSITE_TARGET_ASSETS`；`cli.py` 把它传给 `create_site_app`。

### 已实现：验收脚本归位

```
scripts/control.py                    # 只剩运维 CLI
tests/acceptance/
  README.md                           # 为什么不在 pytest 里、怎么跑、如何加套件
  _harness.py                         # 共用基建（无业务断言）
  check_admin_ui.py
  check_target_pages.py
```

- `_harness.py` 抽出 `Results`、`admin_request`（绕代理）、`reset_server`、`apply_scenario`、`ConsoleLog`、`read_token`、`parse_common_args`、`run_as_script`。两个套件各自只剩业务断言，入口统一为 `run_as_script(run)`。
- 删除空目录 `web/targets/{react,shared,vue}/`（旧的空壳）、`tests/browser/`、`scripts/.gitkeep`、`src/mocksite/site/static/`。

### 新增回归测试

- `test_asset_resolution_prefers_the_packaged_copy` — 断言包内路径在 `mocksite/_static`、仓库回退指向 `web/targets`，且解析顺序正确。生产镜像删掉 `web/` 后若仍优先仓库路径，会以「assets not found」启动失败，这条测试锁住该回归。
