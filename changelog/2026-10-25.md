## 已实现：阶段 1 状态内核

- 新增 `src/mocksite/state/models.py`：不可变（`frozen`）状态模型 `State`/`BusinessData`/`Product`/`Item`/`Presentation`/`Faults`，全部 `extra="forbid"`；`revision` 位于 `State` 且只读。价格以 `Decimal` 持有、以十进制字符串出入：仅接受 `<digits>[.<digits>]`（可带前导 `+`），拒绝浮点、指数、负号、非有限值与超过 64 字符的输入，`000128.50` 归一化为 `128.50`。呈现控制使用互斥枚举（`product_price`: `normal|empty|missing|renamed`，`item_price`: `normal|renamed`），避免布尔开关互相冲突。`page_count` 由 `items` 与 `page_size` 派生，不存储。
- 新增 `src/mocksite/state/patch.py`：实现 `PATCH` 语义——对象递归合并、数组整体替换；`null`、任意深度的 `revision`、未知 section/key、类型错误一律拒绝，错误以 `{"loc","msg"}` 列表返回，一次给出全部问题；被拒绝的 patch 不会留下部分更新。
- 新增 `src/mocksite/state/store.py`：`StateStore` 持有一把锁，`_commit_locked` 在同一临界区内完成“递增 revision → 渲染静态页 → 同时替换 state 与 `static_html`”，因此不存在“状态已更新而静态页仍旧”的窗口；渲染抛错时状态与页面都不前进。提供 `patch`、`apply_scenario`、`reset`（均返回前后状态或新状态）、`snapshot()` 原子读取、`register` 场景注册。模块不导入任何 Web 框架。
- 新增 `src/mocksite/scenarios/registry.py`：13 个预设场景（`baseline`、`no_change`、`price_change`、`item_price_change`、`empty_value`、`missing_node`、`structure_break`、`empty_list`、`field_rename`、`duplicate_rows`、`pagination_grow`、`outage`、`slow_site`），每个都从默认数据构造完整目标状态并一次性提交，场景之间不叠加；元数据含 `description`、`affects`、`pages`，供 `GET /_admin/scenarios` 使用。`build_default_store()` 返回已注册全部场景的 store。
- 新增 `src/mocksite/state/__init__.py`、`src/mocksite/scenarios/__init__.py` 导出公共名字；新增单元测试 `tests/unit/test_state_models.py`、`test_state_patch.py`、`test_state_store.py`、`test_scenarios.py`。

## 已实现：阶段 2 双端口 HTTP

- 新增 `src/mocksite/config.py`：`Settings.from_env()` 读取 `MOCKSITE_TOKEN`（少于 32 个非空白字符即拒绝启动）、`MOCKSITE_SITE_PORT`/`MOCKSITE_ADMIN_PORT`（默认 9000/9001，必须不同）、`MOCKSITE_SITE_HOST`/`MOCKSITE_ADMIN_HOST`、`MOCKSITE_ADMIN_DIST`、`MOCKSITE_LOG_LEVEL`。`token` 字段设 `repr=False`，避免进入日志与 traceback。
- 新增 `src/mocksite/cli.py` 与 `mocksite` console script：同一进程、同一事件循环内并发运行两个 `uvicorn.Server`，共享一个 `StateStore`；不启用多 worker。只有站点 server 安装信号处理器，任一监听器退出即取消另一个；`--check` 只校验配置不绑定端口。
- 新增 `src/mocksite/site/render.py`、`site/templates/product.html`、`site/routes.py`：Jinja2 自动转义 + `StrictUndefined`；`/static/product` 返回提交时预渲染的 HTML，`/ssr/product` 按当前快照渲染，`/api/data` 输出业务数据 + `revision` + 派生 `page_count`，`/health` 返回 `{"status":"ok"}`。全部业务响应带 `X-Mocksite-Revision` 与 `Cache-Control: no-store`。
- 新增 `src/mocksite/admin/auth.py`、`admin/api.py`：`secrets.compare_digest` 常量时间比较 Bearer token，未认证返回 401 且不返回状态；实现 `GET/PATCH /_admin/state`、`POST /_admin/reset`、`GET /_admin/scenarios`、`POST /_admin/scenario/{name}`，写操作返回完整状态或 `before`/`after`，未知场景 404；流式读取请求体并按 64 KiB 上限返回 413，非 `application/json` 返回 415，空体与坏 JSON 返回 400；日志仅记录方法、路由模板、状态码与 revision。管理端口在 `MOCKSITE_ADMIN_DIST` 存在时托管 `index.html` 与 `/assets`，缺失时返回 503 而不伪造成功。
- 新增 `StateStore.set_renderer()`，启动时把 Jinja2 渲染器注入内核并刷新预渲染页；内核仍不依赖 Jinja2。
- 故障注入中间件只作用于站点业务路由：`/health` 与 `/static/assets` 放行，`outage` 优先于 `delay_ms`，管理端口完全不受影响。
- 新增 `tests/integration/`（`harness.py` 在临时端口上真实启动两个监听器，`conftest.py` 提供 `stack` fixture）：站点契约 21 项、管理契约 34 项；新增 `tests/unit/test_config.py` 20 项。
